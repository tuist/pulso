- Unkeyed coalescing is implemented and validated, default disabled. KEYED coalescing remains deferred: durable alias keys must suppress individual retries across differently grouped batches and CAS conflicts; on conflict a combined segment may need re-encoding after dropping already-published keys. Retirement aliases alone can create duplicate rows if another writer publishes overlapping batches. Requires explicit version/migration/retry-horizon design; do not casually merge keyed requests.
- Immutable segment cache with bounded node-local byte budget; invalidate missing cleanup snapshots, never cache manifest freshness; compare cold and warm queries and track hit rate/heap. Current object store query reads every segment each time.
- Bounded complete log service and generic metric-label summaries now implemented. Posting indexes remain useful for high-cardinality values and present selective labels where summary budgets are exceeded; avoid adding a sidecar PUT per tiny append that cancels ingest cost savings.
- Manifest size grows with lifetime appends and permanent retirement tombstones. Retained VERSION HISTORY can make rewrite-byte costs quadratic even though current object bytes stay linear. Model daily peaks/history explicitly; validate Tigris versioning/soft-delete support first. Partitioned immutable manifest pages/fixed bounded tails would reduce amplification; require durable retry horizon and migration/CAS/query snapshot design. Bucket history/lifecycle policy is not a code-level fix, and deletion must not break active data or compaction recovery.
- Float BYTE_STREAM_SPLIT and forced timestamp delta packing discarded (larger bytes on broad mixed values). ID delta lengths, bounded extrema64B, chunk stats/no offset indexes, and adaptive metric rowgroups kept with small measured byte wins and independent holdout tradeoffs. Further codec microtuning is lower priority than request/history amplification; no universal compression improvement claims.
- Storage cost model excludes compute, retries outside fixture, version history, compaction overlap daily peaks, notifications. Extend lifecycle scenario before compaction policy changes. Add concurrency heldouts 1/2/8/32 producers with heterogeneous sizes and failures, not only five synchronized requests. Validate production economics only with independent provider metering; never deploy automatically.

Use selective binary ownership to avoid input pinning, but acknowledge request processes may still hold original payloads while awaiting ACK. Measure CPU/copy costs and don't pretend per-buffer estimates are heap ceilings.
